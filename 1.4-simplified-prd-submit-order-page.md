# Part 1.4: Simplified PRD – Submit Order Page

E-commerce System MVP – Product Manager Assignment

**Feature chosen:** Submit Order Page. It is where the cart becomes a commitment, so it connects pricing, inventory, address and payment, and its rules decide whether the core flow works.

| Item | Detail |
|---|---|
| Version | v1.0 (MVP) |
| Priority | P0 |
| Platform | Customer-side web / mobile web (H5) |
| Entry points | Shopping Cart → "Checkout"; Product Detail Page → "Buy Now" |
| Exit points | Payment page (success); Cart or Product Detail (failure or back) |

## 1. Feature Background

The core transaction flow is Browse → Add to Cart / Buy Now → **Submit Order** → Pay → Ship → Complete. Submit Order is the only step that creates an order record. Four problems must be solved here:

1. **Overselling.** Several buyers may target the last units at the same time.
2. **Price and availability drift.** Prices, stock and shelf status can change between "Add to Cart" and checkout.
3. **Duplicate orders.** Double taps and network retries can create two orders for one purchase.
4. **Drop-off.** Every extra field or confusing message at this step directly reduces conversion.

## 2. User Goal

| Role | Goal |
|---|---|
| Customer | Confirm what I am buying, where it goes and how much I will pay, then place the order in as few steps as possible, with no surprises in price or availability. |
| Business | Capture a valid, fulfillable order with reserved stock, a correct price snapshot and a complete shipping address. |

**Success metrics:**

- Checkout-to-order conversion rate
- Order submission failure rate, split by reason (stock, off-shelf, price change, system error)
- Duplicate order rate (target: 0)

## 3. Scope

**In scope (MVP):** order confirmation, address selection and entry, item and price summary, buyer note, stock lock, order creation, redirect to payment.

**Out of scope (later iterations):** coupons and points, shipping fee calculation by region (MVP uses a flat fee or free shipping), invoices, multiple shipping addresses per order, gift options, split orders by warehouse.

## 4. Main Flow

1. Customer taps "Checkout" (cart) or "Buy Now" (product page).
2. System **re-validates** each item: on shelf, SKU exists, stock sufficient, current price.
3. Page shows address, item list, price summary and a "Submit Order" button.
4. Customer confirms or edits the address, optionally adds a note, and taps "Submit Order".
5. System runs a single transaction: re-validate, lock stock, create the order (status **Pending Payment**) with a price snapshot and payment deadline.
6. Customer is redirected to the payment page.

## 5. Page Fields

### 5.1 Shipping Address Block

| Field | Type | Required | Rules |
|---|---|---|---|
| Recipient name | Text | Yes | 1–50 characters |
| Phone number | Text | Yes | Valid format for the target market |
| Region (country/state/city) | Selector | Yes | Selected from a predefined list |
| Detailed address | Text | Yes | 5–200 characters |
| Postal code | Text | Depends on market | Validated if the market requires it |
| Set as default | Checkbox | No | Only one default address per user |

**Display:** The default address is pre-selected. If the user has no address, an inline "Add address" form is shown first. A "Change" link opens the saved address list.

### 5.2 Item List Block

| Field | Source | Notes |
|---|---|---|
| Product image | Product | Thumbnail |
| Product title | Product | Max 2 lines, truncated with ellipsis |
| SKU specification | SKU | e.g., "Black / 128GB" |
| Unit price | SKU | Current price at page load |
| Quantity | Cart / Buy Now | Display only on this page (editable via "Back to cart") |
| Line subtotal | Calculated | Unit price × quantity |
| Stock warning | System | Shown only when stock ≤ 5, e.g., "Only 3 left" |

### 5.3 Price Summary Block

| Field | Calculation |
|---|---|
| Items subtotal | Sum of line subtotals |
| Shipping fee | Flat fee or 0 (MVP configuration) |
| Amount payable | Items subtotal + shipping fee |

### 5.4 Other Elements

| Element | Rules |
|---|---|
| Buyer note | Optional, max 200 characters, plain text only |
| "Submit Order" button | Always shows the amount payable. Disabled when there is no valid address or no valid items. Shows a loading state after tap. |
| Back link | Returns to cart (or product page for Buy Now) without creating any order |

## 6. Business Rules

| # | Rule |
|---|---|
| BR1 | **Stock is locked at order submission, not at "Add to Cart".** The lock is released on cancel or payment timeout, and converted to a deduction on payment success. |
| BR2 | **Atomic stock check.** Locking uses a conditional update (lock only if available stock ≥ requested quantity). If any item fails, the whole order fails and no stock is locked. |
| BR3 | **Re-validation on page load and again on submit.** Checks: product on shelf, SKU active, stock sufficient, price current. |
| BR4 | **Price snapshot.** The order stores the unit price, title and SKU at submission time. Later price edits never change existing orders. |
| BR5 | **Price change before submission.** If the price changed since the customer last saw it, the page refreshes, shows "Price updated", and requires the customer to tap "Submit Order" again. |
| BR6 | **Off-shelf or invalid items cannot be ordered.** They are removed from the order list and the customer is told. If no valid items remain, submission is blocked. |
| BR7 | **Quantity limits.** Minimum 1, maximum per order line = min(available stock, per-order limit, e.g., 99). |
| BR8 | **Payment deadline.** Every order gets a payment deadline (default 30 minutes, configurable). Unpaid orders are auto-cancelled and stock is released. |
| BR9 | **Idempotent submission.** Each checkout session carries a unique token. Repeated submissions with the same token return the same order instead of creating a new one. |
| BR10 | **Order number.** Unique, system-generated, not guessable (timestamp + random suffix). |
| BR11 | **Address snapshot.** The order stores a copy of the address. Later edits to the saved address do not affect existing orders. |
| BR12 | **Login required.** Guests are redirected to login and returned to this page afterwards with the cart preserved. |
| BR13 | **Partial availability.** If some items are unavailable, the customer may continue with the remaining valid items after explicit confirmation. The system never silently drops items. |
| BR14 | **Buy Now isolation.** Buy Now creates a temporary single-item checkout and does not alter the shopping cart. |

## 7. Error Messages and Exception Handling

| # | Scenario | Trigger | Message (user-facing) | System Behavior |
|---|---|---|---|---|
| E1 | Insufficient stock | Stock < requested at page load or submit | "Sorry, only {n} left for {Product}. Please reduce the quantity or remove it." | Order not created, no stock locked. Customer returns to cart with the item highlighted. |
| E2 | Product off sale | Item taken off shelf after being added to the cart | "{Product} is no longer available and has been removed from your order." | Item excluded and total recalculated. If none remain, "Submit Order" is disabled with a "Back to shopping" link. |
| E3 | Price changed | Current price ≠ price last shown | "The price of {Product} has been updated to {new price}. Please review before submitting." | Page refreshes with new price. Customer must confirm by tapping "Submit Order" again. |
| E4 | No address | Address not selected | "Please add a shipping address." | Button disabled, address block highlighted. |
| E5 | Invalid address field | Field fails validation | Inline message, e.g., "Please enter a valid phone number." | Submission blocked, focus moves to the first invalid field. |
| E6 | Duplicate tap / retry | Same token submitted again | No error shown. | Existing order returned, customer continues to payment. |
| E7 | Concurrent last-unit conflict | Two buyers submit for the last unit | Same as E1 for the losing buyer. | Atomic stock lock guarantees exactly one winner. |
| E8 | System or network error | Timeout or server error during submit | "Something went wrong. Your order was not placed. Please try again." | Transaction rolled back, no stock locked. Retry is safe because of BR9. |
| E9 | Session expired | Login lost | "Your session has expired. Please log in again." | Redirect to login, then back to this page. |
| E10 | Quantity exceeds limit | Quantity > per-order limit | "Maximum {n} per order for {Product}." | Customer returns to cart to adjust. |

**Order status after submission:** (none) → Pending Payment. Stock status: Available → Locked. If any exception above blocks submission, no order is created and nothing is locked.

## 8. Acceptance Criteria

| # | Given | When | Then |
|---|---|---|---|
| AC1 | Logged-in customer with valid items and a default address | Opens checkout | Items, price summary and default address are displayed, and "Submit Order" is enabled. |
| AC2 | Valid items, valid address | Taps "Submit Order" | One order is created with status Pending Payment, stock is locked, a payment deadline is set, and the customer lands on the payment page. |
| AC3 | Order created | Product price is edited afterward | The existing order keeps the original price and address. |
| AC4 | Requested quantity exceeds stock | Opens checkout or submits | Message E1 is shown, no order is created, no stock is locked. |
| AC5 | Only 1 unit left, two customers submit at the same moment | Both tap "Submit Order" | Exactly one order is created. The other customer sees E1. Stock never goes negative. |
| AC6 | One item was taken off shelf, others are valid | Opens checkout | Off-shelf item is excluded with message E2, the total is recalculated, and the customer can still submit the rest. |
| AC7 | All items taken off shelf | Opens checkout | "Submit Order" is disabled, and a "Back to shopping" link is shown. |
| AC8 | Price changed since the customer last saw it | Taps "Submit Order" | Message E3 is shown with the new price. No order is created until the customer confirms. |
| AC9 | Customer has no saved address | Opens checkout | Address form is shown, and "Submit Order" is disabled until it is valid. |
| AC10 | Customer double-taps "Submit Order" | Two requests arrive | Exactly one order exists, and the customer proceeds to payment normally. |
| AC11 | Order created and not paid within the deadline | Deadline passes | Order becomes Cancelled and locked stock returns to available. |
| AC12 | Server error during submission | Taps "Submit Order" | Message E8 is shown, no order exists and no stock is locked. Retrying works normally. |
| AC13 | Customer used "Buy Now" | Completes or abandons checkout | The shopping cart contents remain unchanged. |
| AC14 | Guest user | Tries to reach checkout | Redirected to login, then returned to checkout with items preserved. |

## 9. Dependencies

- **Product and SKU service:** shelf status, price, stock
- **Inventory service:** atomic stock lock and release
- **User service:** login state and saved addresses
- **Order service:** order creation and status machine
- **Payment service:** payment page and callback (next step in the flow)
- **Scheduler:** payment-timeout auto-cancel job
