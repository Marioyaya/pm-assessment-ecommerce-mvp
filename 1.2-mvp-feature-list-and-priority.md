# Part 1.2: MVP Feature List and Priority

E-commerce System MVP – Product Manager Assignment

**Prioritization logic:** P0 is anything the core flow (Browse → Cart/Buy Now → Submit Order → Pay → Ship → Complete) cannot run without. P1 is anything that reduces friction, risk or manual work but has a workable fallback. P2 is anything that drives growth or retention rather than transaction completion.

## Customer Side

| Module | Feature | Priority | Reason |
|---|---|---|---|
| Customer Side | Login / Registration (phone or email + verification code) | P0 | Orders, addresses and payments must be tied to an identity |
| Customer Side | Third-party login (WeChat, Google, etc.) | P2 | Convenience only; basic login already works |
| Customer Side | Product List (basic list with image, title, price, pagination) | P0 | Customers need an entry point to discover products |
| Customer Side | Product Detail Page (images, price, SKU selector, stock status, description) | P0 | Customers must see product information and select a SKU before ordering |
| Customer Side | Category Filter (one-level or two-level navigation) | P0 | Minimum browsing structure; without it a catalog of any size is unusable |
| Customer Side | Keyword Search (basic title match) | P1 | Greatly improves findability, but customers can still browse by category in a small catalog |
| Customer Side | Search sorting and advanced filters (price, sales, rating) | P2 | Optimization for larger catalogs, not needed to validate the flow |
| Customer Side | Shopping Cart (add, edit quantity, remove, select items) | P0 | Part of the defined core flow and supports multi-item purchases |
| Customer Side | Buy Now (single item, skip cart) | P1 | Shortens the path for single-item purchases; cart still covers the need |
| Customer Side | Submit Order (address, item confirmation, price summary, stock check) | P0 | This is where the order is created; no order means no transaction |
| Customer Side | Address Management (add, edit, set default) | P0 | Shipping requires a valid address; can be a simple form in MVP |
| Customer Side | Payment (one primary online channel, payment result page, timeout handling) | P0 | Without payment there is no revenue and the flow cannot proceed to shipment |
| Customer Side | Multiple payment channels | P2 | One reliable channel is enough to validate; add more by market demand |
| Customer Side | Order List / Order Detail (status, items, amount, logistics info) | P0 | Customers must confirm the order succeeded and track its progress |
| Customer Side | Cancel Order (unpaid orders, and paid orders before shipment) | P0 | Basic user control and a prerequisite for releasing locked stock |
| Customer Side | Refund (full refund for cancelled paid orders) | P1 | Needed for trust and compliance, but can be handled manually by the admin at first |
| Customer Side | Return / after-sales workflow (partial refund, return logistics) | P2 | Complex process; not required to complete the core flow |
| Customer Side | Confirm Receipt (with auto-confirm after N days) | P1 | Closes the loop to "Complete Order"; auto-confirm can cover the gap |
| Customer Side | Coupons, points, promotions | P2 | Growth features; not required for the basic transaction flow |
| Customer Side | Reviews and ratings, wishlist, recommendations | P2 | Retention and conversion boosters for later iterations |

## Admin / Operations Side

| Module | Feature | Priority | Reason |
|---|---|---|---|
| Admin Side | Product Management (create, edit, price, on/off shelf, images) | P0 | Products must exist before they can be sold |
| Admin Side | Category Management | P0 | Needed to support customer-side category navigation |
| Admin Side | SKU / Inventory Management (SKU creation, stock view, manual adjustment) | P0 | Prevents overselling and is required to confirm availability at order time |
| Admin Side | Low-stock alert | P1 | Improves operational efficiency; staff can check manually at first |
| Admin Side | Bulk import/export of products and stock | P2 | Efficiency tool for large catalogs; manual entry works for MVP |
| Admin Side | Order Management (list, filter by status/time/order no., view detail) | P0 | Operations must see paid orders to fulfill them |
| Admin Side | Abnormal order handling (manual close, manual refund, status correction) | P1 | Safety net for payment or stock anomalies; low volume early on, but critical for trust |
| Admin Side | Shipment Management (select carrier, enter tracking number, mark as shipped) | P0 | Without it the flow cannot move from Paid to Shipped |
| Admin Side | Logistics API integration and auto-tracking | P2 | Manual tracking number entry is enough for MVP |
| Admin Side | Batch shipping and print shipping labels | P2 | Efficiency optimization for higher order volume |
| Admin Side | User Management (staff accounts, basic role permissions: operations vs. admin) | P1 | Needed for access control and audit, but a single shared role can work in early testing |
| Admin Side | Customer account management (view, disable) | P2 | Not needed for transactions; mainly a risk-control feature |
| Admin Side | Data Dashboard (orders, GMV, payment success rate, conversion funnel) | P1 | Essential to evaluate the MVP, but not required for orders to flow; can start with simple metrics or a database query |
| Admin Side | Advanced analytics and reports | P2 | Deeper analysis can wait until there is enough data |

## Summary

- **P0 (core loop):** login, product browsing and detail, category, cart, order submission, address, payment, order viewing, cancellation, and on the admin side product, category, inventory, order and shipment management. These form the minimum closed loop where a customer can buy and the team can ship.
- **P1 (experience and control):** search, Buy Now, refund, confirm receipt, low-stock alert, abnormal order handling, staff permissions and a basic dashboard. Each has a workable manual fallback, so they can follow immediately after the P0 launch.
- **P2 (growth and scale):** coupons, reviews, recommendations, third-party login, bulk tools, logistics integration and advanced analytics. These support growth rather than transaction validity.

**Scoping note:** "Buy Now" appears in the background flow, but I rated it P1 because the cart already completes the same path. If the business expects mostly single-item purchases, it can be promoted to P0 at little extra cost.
